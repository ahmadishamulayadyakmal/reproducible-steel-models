# W03 · `libthermo` skeleton

**Epic:** E01 · **Tag:** w03 · **Date:** 2026-11-24
**Reference:** R16 (Voller & Prakash 1987 — the future solver benchmark)

## Promised scope

- [x] `fpm.toml` with source and test directories under `src/fortran/libthermo/`
- [x] `libthermo` module with explicit kinds and no implicit typing
- [x] At least one unit test runnable with `fpm test`
- [x] CI matrix entry that builds and tests the Fortran package

## What was actually completed

- Added `fpm.toml` with `[library] source-dir`, an explicit `[[test]]` target
  (`test_libthermo`), `auto-tests = false`, `implicit-typing = false`, and
  `implicit-external = false`. Manifest keys were checked against the current
  fpm reference; top-level `src-dir`/`test-dir` are **not** valid keys.
- Added `src/fortran/libthermo/src/libthermo.f90` exposing `dp` (double
  precision), the package version, and Celsius↔Kelvin conversion helpers with
  a pure-function interface.
- Added `src/fortran/libthermo/test/test_libthermo.f90`, a dependency-free test
  program that checks round-trip conversion and the version string using
  `error stop`.
- Documented the module in `src/fortran/libthermo/README.md`.

## What failed / was not completed

- `gfortran` and `fpm` are **not installed** on the development host, so
  `fpm test` could not be executed locally. The Fortran code is unverified
  until it runs in CI.
- `test-drive` / `pFUnit` were not integrated. The current test uses a small
  self-contained assertion helper so that `fpm test` works with zero external
  dependencies; a framework should be introduced with the solver tests in W09.
- No physics kernels exist yet — this sprint is a build-and-test skeleton only.

## Technical decisions

- Keep conversion helpers in the library instead of duplicating unit handling
  across future solvers; SI remains the internal convention.
- Prefer a dependency-free first test so that a broken network in CI cannot
  hide a compiler problem.
