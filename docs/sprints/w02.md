# W02 · Reproducible environment

**Epic:** E01 · **Tag:** w02 · **Date:** 2026-11-24
**Reference:** R31 (Oberkampf & Roy 2010 — reproducibility of computational results)

## Promised scope

- [x] `pixi.toml` and `environment.yml` pinning Python and the Fortran toolchain
- [x] `Dockerfile` for a clean, non-interactive environment
- [x] CI hello-world matrix on Ubuntu and Windows (Python + Fortran)
- [x] `test` / `all` / `figures` recipes in `justfile`

## What was actually completed

- Defined a conda-forge based environment with Python 3.11, `gfortran`, and
  `fpm` 0.12 in both `pixi.toml` and `environment.yml`.
- Added a `mambaorg/micromamba` based container that creates the same
  environment from `environment.yml` and runs both test suites at build time.
- Added `.github/workflows/ci.yml` with an Ubuntu + Windows matrix. CI installs
  the package in editable mode with dev extras, runs `pytest`, then runs
  `fpm test`.
- Added a sprint issue template under `.github/ISSUE_TEMPLATE/`.

## What failed / was not completed

- The container image was **not built locally**: Docker is not installed on the
  development host. The Dockerfile is unvalidated until CI or WSL2 is available.
- CI itself has not run because no remote exists. The matrix is configuration
  only, not evidence of a green build.
- `just` is not installed locally; recipes were syntax-reviewed but not executed.

## Technical decisions

- A single conda-forge environment is the source of truth for both pixi and CI;
  this keeps Linux, Windows, and Docker on the same package versions.
- CI uses `mamba-org/setup-micromamba` rather than installing `fpm` from source,
  avoiding a slow cargo build in every job.
